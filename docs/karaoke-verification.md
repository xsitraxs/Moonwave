# Караоке — протокол проверки перед релизом

Задача: отсмотреть караоке (синхронный текст, пословная подсветка) в **живом Electron** на машине, где окно реально открывается и играет звук. В среде, где разрабатывался аудит, скачать Electron-бинарник было нельзя, поэтому проверка там шла статически и под jsdom; этот документ — для финального «глазами + ушами» прогона.

Кандидат на прогон — ветка `arena/abe26986-moonwave`, изменения **не закоммичены** (сознательно: сначала прогон, потом коммит):

```
git status --short
#  M eslint.config.mjs
#  M src/renderer/src/components/player/LyricsPanel.tsx
#  M src/renderer/src/components/player/NowPlaying.tsx
#  M src/renderer/src/i18n/en.ts / ru.ts
#  M src/renderer/src/styles/globals.css / now-playing.css / studio-shell.css
#  ?? src/renderer/src/lib/lyricsTiming.ts (+ .test.ts)
```

Если `git status` показывает другое — остановиться и написать, что именно видно.

## 0. Прогон до запуска

```sh
npm ci                 # или npm install, если посткаталой Electron подхватывается сетью
npm run typecheck      # чисто
npm run lint           # чисто
npm test               # ожидается: # pass 375, # fail 0
SKY_DEMO=1 npm run dev # альтернативно: npm run dev:debug (удалённая отладка на порту 9223)
```

Заметки о демо-режиме (`src/main/demo.ts`): `SKY_DEMO=1` работает только в незапакованной сборке; подставляется отдельный `userData` («Moonwave demo»); треки — выдуманные названия (кириллица и латиница), обложки — сгенерированные SVG; вместо потока SoundCloud играет тихий локальный тон 220 Гц (WAV data URL, ~30 с). Сеть и аккаунт SoundCloud **не нужны**. TTML с пословной разметкой в демо не подгружается (см. п. 9 и Plan B).

## Как дойти до караоке за 5 минут

1. Взять любой трек, добавить в очередь, нажать Play.
2. Открыть полноэкранный плеер → вкладка «Текст».
3. В демо-режиме текста обычно не найдётся: внизу появится «Вставить свой текст» — вставить 10–16 любых строк (по строке на строку песни) → «Сохранить для этого трека».
4. Нажать «Разметить нажатиями» (слева от «Сохранить»), нажать «Старт» и тапать (Пробел / кнопка «Тап») в начале каждой строки; Backspace отменяет последнюю; в конце — сохранить.
5. Слова начнут подсвечиваться пословно.

## Сценарии

Правила: каждый пункт — «СДЕЛАНО / БАГ / ПРОПУЩЕНО (причина)», при баге — что именно, каким треком/вкладкой, скриншот и кусок консоли (View → Toggle Developer Tools). Время строки «минус плановое» отмечаем терпимо: среда и железо разные.

1. **Окно и вкладка текста.** Плеер открывается без розового экрана, консоль без красных ошибок; список строк рендерится; скелетон исчезает после загрузки.
2. **Свои слова сохраняются и показываются.** После сохранения свои строки видны во вкладке; перезапуск приложения — строки на месте (own lyrics из локального файла).
3. **TapSync: разметка.** Линии получают времена в порядке строго по возрастанию; «Назад» отменяет последнюю метку; «Заново» спрашивает подтверждения и при отмене оставляет метки нетронутыми (новое поведение); после сохранения текст показан как LRC.
4. **Подсветка с линейными (тапнутыми) таймингами.** Каждая строка загорается ровно в свой тап (±0.1 с); внутри строки свет «перетекает» слева направо по длинам слов; слова никогда не «мигают»/не белеют мгновенно в случайных местах, пустых заливок нет.
5. **Быстрый рэп.** Тапать строки каждые ~0.8–1.2 с хотя бы на 8 строк: строки переключаются без заметного опоздания (>200 мс), прокрутка практически мгновенна (класс `fast`), свет не «догоняет» голос.
6. **Пауза и перемотка.** На паузе свет стоит; перемотка на паузе — свет перемещается сразу; Play — продолжает с нужного места.
7. **Клик по строке.** Мгновенный seek на эту строку + автоскролл резюмируется; текущая строка — та, на которую кликнули.
8. **Ручной скролл.** Колесо мыши ИЛИ стрелки/PageUp/PageDown/Space на списке: автоскролл ставится на паузу; появляется кнопка «К текущей строке»; клик по ней возвращает к текущей (быстро/плавно — зависит от режима). Снова 4+ секунды без ручного скролла — автоскролл сам возобновляется.
9. **Фоновый вокал (`.w.bg`).** Доступен только через источник с пословной разметкой и `x-bg`-ролью (TTML от Better Lyrics; нужна сеть и хит для конкретного трека — слова в скобках в TTML). Ожидание: такие слова — курсив, ~0.78 em, акцентным цветом, подсвечиваются тем же `--k`. Если проверить нельзя — ПРОПУЩЕНО и прогон Plan B (там есть 2 такие строки: «шё-о-ом», «ла-ла-ла»).
10. **Инструментальные разрывы.** Между строками с разрывом >4–5 с подсветка отсутствует вовсе (ничего не горит); при word-timed источнике на разрыве рисуется «♪» (с «дыханием»). Живо проверяется в Plan B.
11. **Смена трека на играющем плеере.** На следующий трек список моментально перескакивает к текущей строке (не «едет» с самого верха), подсветка соответствует новым таймингам; ошибка/пустота при отсутствии текста не роняет плеер.
12. **Окно не в фокусе / скрыто.** При потере фокуса (другое окно поверх) — CSS-анимации замирают (html[data-activity="blurred"]), цикл rAF не крутится вхолостую; при сворачивании/скрытии — полный останов (html[data-activity="hidden"]). DevTools → Performance: в фоне почти нет кадров с работой karaoke-цикла; при возврате фокуса подсветка продолжается с правильного места.
13. **prefers-reduced-motion** (системная настройка «уменьшить движение»): слова загораются целиком (0 → 100%, без «wipe»), переходы строк мгновенные, скролл без плавности. Включить в ОС, перезапустить, повторить п.4 и п.7.
14. **Темы и размеры окна.** Студия (по умолчанию) и скетч: «дальние» строки читаемы на пёстрой обложке; окно сузить до ~900 px — нет горизонтального скролла и обрезаний; широкое окно (≥2К) — текстовая колонка ограничена, строки не растягиваются бесконечно; очень длинный заголовок трека — макет не ломается.
15. **Ручной поиск («Найти слова» / ManualSearch).** Гиббериш → «Ничего не подходит» (у <p role="status">); с сетью — результаты приходят; две быстрых подряд — показывается ответ на последнюю (устаревший затирается); без сети — понятная ошибка вместо бесконечного спиннера.
16. **Производительность на слабой машине.** Открыть Performance, записать ~30 с воспроизведения: кадр ≤ ~16 мс, нет принудительной синхронной компоновки от karaoke-кода (в rAF только стиль активных слов); память от точки к точке стабильна (±20–30 МБ за 5 мин).
17. **Поведенческие мелочи.** Последние строки трека (нет следующего) — подсветка корректно доигрывается до конца; дублирующиеся/невалидные тайминги (если зайти через редактор с битым LRC) не дают NaN и «белых квадратов»; плейлист заканчивается — плеер переходит или корректно останавливается, без зависания.

## Plan B — без живого Electron

Если в окружении прогона Electron тоже не поднять, то же самое (кроме звука и реальных GPU-fps) видно в браузере:

```sh
npm run build                 # out/renderer
node demo-preview/gen.mjs     # синтезирует demo.wav (в git не лежит — *.wav игнорируется)
node demo-preview/stub.mjs    # → demo-preview/app + внешний demo-stub.js (CSP-safe)
node demo-preview/serve.mjs   # http://localhost:4173 (редирект на /index.html?sc-debug)
```

Демо: трек «Ночной экспресс (Midnight Express)» — лунный кот, ~96 с, word-timed текст RU/EN, 2 инструментальных паузы (~36 с и ~67.5 с), 2 фоновых вокала (курсивом, акцентным), 16 строк / 86 слов. Браузер блокирует автозвук — нажать **Play**. Без внешних запросов (файл .wav локально, range-запросы вкл.). Что здесь НЕ проверяется: качество анимаций под реальным GPU, реальный вывод на динамики, окно/фокус/hidden.
